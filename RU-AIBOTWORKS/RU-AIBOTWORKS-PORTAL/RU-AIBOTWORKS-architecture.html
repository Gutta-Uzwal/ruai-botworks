Architecture

Seven planes, five lanes, one gate

The line that matters runs between what proposes and what authorises. If the model is on both sides of it, the architecture is wrong.

The seven planes

This repository is not a runtime, so it owns four planes and declares the other three as deployment obligations. Naming the gap is itself a control — a repository that claims to enforce sandboxing it does not run is worse than one that says so.

PlaneResponsibilityTrustStatus
1 · ControlStarts, stops, schedules, budgets. Holds the kill switch.Fully trusteddeployment obligation
2 · PolicyEvaluates every tool call: who, what, where, which tier, what budget.Fully trusted, deterministicowned here
3 · IdentityIssues short-lived scoped credentials. Records the human principal.Fully trusteddeployment obligation
4 · ReasoningThe model, the prompt, the planner. Decides what to do next.UNTRUSTEDowned here
5 · ExecutionWhere model-generated code actually runs.HOSTILE — assume compromisedeployment obligation
6 · Tool & dataThe registered tool surface and the systems behind it.Trusted code, untrusted callersowned here
7 · ObservabilityTraces, tool-call log, provenance, receipts.Fully trusted, append-onlyowned here
What this repository does not do. It does not run a kernel-isolated sandbox, issue credential leases, or host an out-of-band kill switch. Those are the control, identity and execution planes, and they are production deployment requirements. The database has tables for kill-switch and restore drills (ops.KillSwitchDrill, ops.RestoreDrill) precisely so that the absence of a dated, measured record is visible rather than assumed.

Delivery lanes

One lane per project, chosen by web-architect at Architecture and recorded in that project's DESIGN.md. A project never carries two.

LaneWhat it buildsStackChosen when
ADatabase-backed webDjango + ReactAccounts, data, workflows
BStatic-first webVite + React, no DBContent-heavy, Core Web Vitals critical
C1Android nativeKotlin + Jetpack ComposeAndroid-only, premium UX, deep platform integration
C2Cross-platform mobileFlutter / Dart 3Android and iOS from one budget
C3Mobile companionReact Native + ExpoClient already buying the web lane
The iOS limit, stated at scoping. Xcode is macOS-only. All three mobile sub-lanes build Android on Windows. C2 and C3 write iOS-capable code but cannot compile it here. An iOS deliverable needs a macOS runner budgeted before the project starts — told to the client at scoping, not discovered at release.
